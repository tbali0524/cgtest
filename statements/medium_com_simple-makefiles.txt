Goal
A Makefile is a build script that describes dependencies between dated files, and the actions required to build a target file from its prerequisite files if it is outdated or missing; actions are executed in an order such that every prerequisite is up to date before it is needed.

Your task is to implement a simplified make utility: read a list of preexistingFiles with associated fileTimes, a list of targets to build, and a Makefile, then print the actions that would be executed, in order.

Makefile syntax

A Makefile is a sequence of rules and actions, with optional comments.

Comments
A # character begins a comment that extends to the end of the line. Comments are removed before applying other parsing rules.

Whitespace
After using TAB to identify actions (see below), TAB and other leading and trailing whitespace are ignored, as are blank lines and extra spaces not needed to separate tokens.

Rules

A rule associates targets with prerequisites. Each of these is generally a file, but can be any valid token string:

target1 [target2 ...] : [prereq1 ...]

To the left of the : is a whitespace-separated list of one or more targets. To the right is a whitespace-separated list of zero or more prerequisites. Whitespace adjacent to the : is optional. If multiple targets appear before the :, it is equivalent to writing a separate identical rule for each distinct target.

A target may appear in more than one rule. Its prerequisites are the union of prerequisites in all its rules, and its actions are the concatenation of all associated rule actions, in order of appearance.

Actions

An action is any line that begins with a TAB. It is associated with the preceding rule. Applying the whitespace rules above yields a sequence of tokens. Any token that matches a built-in macro (see below) is replaced by its expansion. When the action is executed, the resulting tokens are printed as a single line of output with single-space delimiters.

Built-in macros

Within an action, built-in macros may appear as whole tokens. They are replaced by their expansions before the line is printed:

| Macro | Expands to
|-------|-----------
| $@    | The target being built
| $<    | The first prerequisite of the associated rule
| $^    | All distinct prerequisites of the rule, space-separated,
|       |   preserving their order in the rule

Build semantics

- Duplicate targets or prerequisites in a rule are ignored.
- If a file exists prior to the build, it has an integer fileTime. The higher the fileTime, the more recently the file was last updated.
- A non-preexisting target, or a preexisting target that is as old or older than any of its prerequisites, is out of date.
- A preexisting file with no prerequisites is up to date.
- Building a target effectively updates its fileTime and makes any target for which it is a prerequisite out of date.
- Before a target is built, all of its prerequisites must be fully up to date.
- If no required targets are explicitly given in cmdArgs, the first target in the first rule of the Makefile is the required target.
- Targets that are not needed to bring the required targets up to date are not built.
- When two targets can otherwise be built in any order, the one whose filename is lexicographically smaller is built first.
- Each target is built at most once.
- A target that has no actions produces no output, but its prerequisites are still built.
- If a circular dependency exists anywhere in the Makefile--even among targets not being built--the build is aborted prior to executing any action.

Example

The following Makefile compiles two source files into object files, then links them into a program.

all: util.o main.o
	gcc -o $@ $^
util.o: util.c
	gcc -c $< -o $@
main.o: main.c
	gcc -c $< -o $@

Assume cmdArgs is empty, so the default target all is built. Assuming main.c and util.c are the only preexisting files, the build proceeds as follows: util.o and main.o are prerequisites of all and must be built first. Between util.o and main.o, neither depends on the other, so the lexicographically smaller name main.o is built first.

The actions output are:

gcc -c main.c -o main.o
gcc -c util.c -o util.o
gcc -o all util.o main.o
[Build complete]

Note that $^ in the all rule expands to util.o main.o—-the prerequisites in their given rule order, not the order they were built.

Input
Line 1: An integer nFiles, the number of preexisting files.
Next nFiles lines: A preexistingFile and its integer timestamp fileTime, one file per line.
Next Line: The commandline arguments cmdArgs, consisting of space-delimited required targets to build, or an empty line.
Next Line: An integer nLines, the number of lines in the Makefile.
Next nLines lines: The contents of the Makefile, one makefileLine at a time.

Output
If a circular dependency is detected:
A single line:
[Circular dependencies detected]

If a circular dependency is not detected:
One line per action executed: The tokens of the action, separated by single spaces,
with all built-in macros already expanded. Actions are printed in the order they are executed.
Final line:
[Build complete]

Constraints
0 <= nFiles <= 20
1 <= length(preexistingFile) <= 100
0 <= fileTime <= 1000
0 <= length(cmdArgs) <= 100
1 <= nLines <= 100
0 <= length(makefileLine) <= 100

preexistingFile consists of printable ASCII characters and does not contain whitespace, $, :, or #.
All fileTime values may be assumed to be in the past.

Within the Makefile:
- All Makefiles are syntactically valid.
- At least one rule is defined.
- Every file consists of 1-100 printable ASCII characters and does not contain whitespace, $, :, or #.
- Every required target either appears as a preexistingFile or is the target of at least one rule.
- $< is only used in actions with a rule having at least one prerequisite.
- Every action is preceded by at least one rule.
- Every action has at least one token.
- TAB characters do not appear anywhere except as the first character of an action.
